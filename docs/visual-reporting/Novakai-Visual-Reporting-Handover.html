Compiled from the conversation. This is the short contractual version; the visual plan below carries the engineering detail.

Outcome — MUST

Build a narrow proof of concept in which one real Codex session and repository evidence compile into one accepted visual work-session report, consumed through the same public contract by Novakai Canvas and a standalone CLI/static view.

Done when — MUST

In scope — MUST

Out of scope — MUST

Fallback — MUST

  • If LikeC4 introduces duplicate authority or private coupling, render the neutral projection with the existing Canvas snapshot renderer.
  • If html-builder cannot expose a public pure adapter, create a minimal semantic HTML renderer local to the POC.
  • Record the integration gap separately; do not expand the mission.

Ownership, effort, escalation

  • One primary agent owns outcome, implementation, and verification.
  • High implementation effort; temporarily max only for unresolved hard debugging.
  • No subagents unless Chris or active repository instructions explicitly request them.
  • Escalate only for safety, irreversible shared state, unavailable authority, dirty-worktree ambiguity that changes the base, or no viable fallback.
  • Close with screenshots, pass/fail evidence, remaining red gates, and exact artifact paths—not a diary.

Target architecture

Is this importing smartly—or just patching repositories together?

It is genuinely composable only if imported tools sit behind seams and one host-neutral capability remains authoritative.

Who owns reporting, and how do the hosts compose it?

Proposed logical module architecture. Dependencies point from caller to contract; dashed edges mean an adapter satisfies a seam.

Proposed
Legend: solid arrow = synchronous call/dependency dashed arrow = adapter satisfies an internal seam green container = authoritative/private behaviour projection = disposable and rebuildable
Smart import means replacing an adapter does not change reporting rules, and adding a second host does not change the core. If either condition fails, the implementation is patching.

Authority rule

Canvas ArchitectureDocument remains the architecture-map authority. LikeC4 receives report projections only. Retiring or replacing the Canvas model requires a separate ADR and is not part of the POC.

Export rule

Rendered HTML never owns report state. It records the accepted report revision and source digest, and can always be discarded and rebuilt.

Tracked publication provenance

Evidence commit means the explicitly named committed code and tree inspected by the report. Publication commit means the following docs/artifact-only commit; it is necessarily excluded from its own evidence. Final generation names the immutable evidence commit rather than ambient HEAD.

Public contract

What is the smallest honest interface?

Names are proposed. Behaviour and authority are mandatory. External inputs enter as unknown and are runtime-validated at the seam.

Commands

  • importSession
  • recordReceipt
  • compileReport
  • acceptReport

Queries

  • listReports
  • readReport
  • readProjection

Events

  • SessionImported
  • ReportDrafted
  • ReportAccepted
  • ExportProduced

Typed identities

  • WorkSessionId
  • ReceiptId
  • ReportRevisionId
  • EvidenceRef value object

Authoritative records

  • WorkSession — normalized imported source and source digest.
  • WorkReceipt — Change, Decision, Proof, Blocker, or Artifact with evidence.
  • ReportDraft — deterministic compilation candidate.
  • AcceptedReport — accepted revision tied to the expected source digest.

Every independently persisted record has id, kind, schemaVersion, and createdAt.

Invariants owned only by the core

  • Exactly one accepted report revision per session/source version.
  • Acceptance fails if the expected source digest is stale.
  • Stable provider event IDs make import retries idempotent.
  • Every important report claim carries evidence and claim status.
  • Renderers cannot mutate authoritative records.
  • Names are presentation data, never durable joins.

Vertical slices

What gets built, in what order, and when do we stop?

Build executable paths through the public contract. Do not create every layer first and hope they meet in the middle.

2–3hStage 0 · bounded spike

Prove the imported tools can remain adapters

Define a tiny neutral ChangeMapProjection. Render it once through LikeC4 and export one semantic report through a public/pure html-builder adapter. Persist nothing. Run the fallback brake after three checks or five minutes.

EXIT: one projection renders; no private imports; no new architecture authority; both fallbacks are proven viable.
3–4hStage 1 · POC core slice

Own one session and one accepted report

Publish runtime schemas, typed IDs, four commands, three queries, typed failures, deterministic compilation, source-digest acceptance, and an in-memory repository. Test only through the public contract.

EXIT: independent harness imports, recompiles identically, rejects stale acceptance, and retries without duplicates.
3–5hStage 2 · POC consumers

Connect Canvas and a genuinely different host

Add one Canvas reporting route/panel and one CLI/static viewer. Both request the same accepted projection. Neither imports private paths. Keep renderer-specific models outside the core.

EXIT: same report revision/source digest visible in both hosts; core unchanged for the second host.
4–8hStage 3 · v1 hardening

Replace fixtures with real evidence and failure proof

Wire the real Codex parser, git/dependency evidence, durable local storage if required, deterministic HTML package, and failure injection. Delete any superseded POC path once the real route passes.

EXIT: one real session produces an accepted report after restart; failure paths are typed; architecture gates and both-host tests pass.

Smart POC · 8–12 AI-hours

Stages 0–2 at deliberately narrow scope: Codex only, in-memory report repository, one visual projection, one report template, two consumers. It proves architecture and product value.

Production-shaped v1 · 16–27 AI-hours

Full contract hardening, real evidence, restart/durability, export packaging, failure injection, architecture tests, and cleanup. This is still not a three-day platform build.

Key assumptions

What is being assumed so the build stays small?

If an assumption changes, re-plan the affected slice instead of quietly expanding the architecture.

Local and single-user first

POC runs locally for Chris. Multi-user identity, permissions, sync, and hosting are out of scope.

Codex first

One Codex provider/session shape proves the source seam. Claude and other agents come later.

Local-only human acceptance

A report draft becomes authoritative only through explicit local acceptance against the expected source and receipts digests. The POC does not claim an authenticated actor, authorization, or multi-user identity.

Canvas truth stays

The existing Canvas architecture document remains the map authority; report projections reference rather than replace it.

Modular monolith

Embedded core plus CLI adapter. No server, queue, worker fleet, or network protocol without runtime evidence.

One useful report shape

The POC proves outcome, change map, sequence, proof, decisions, and next action—not a general report designer.

Source evidence is available

Local session records and repository evidence can be read without introducing a hosted trace platform.

Imported tools are replaceable

LikeC4 and html-builder are conveniences behind adapters. Fallback renderers preserve the mission.

Dirty work belongs to Chris

Existing modified/untracked files are preserved. Implementation happens in a separate clean worktree.
