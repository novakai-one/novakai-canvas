## How the lanes are kept apart

Two rules make parallel builders safe:

1. **A lane owns files exclusively.** No two lanes may edit the same file. If a lane needs a
   change in another lane's file, it reports that as a dependency instead of reaching in.
2. **Contracts between lanes are frozen before any lane starts** and are only changed by the
   lead. A lane codes against a frozen signature, not against another lane's progress.

Everything already proven stays put: records on disk, the library seam, the migration. Existing
diagram data is not precious — it is fewer than 20 diagrams an agent can regenerate — so no lane
should spend effort defending it.

## Frozen contracts

Written before the lanes start. Lane A implements `projectView`; Lane C consumes it. Neither
waits for the other.

- `src/domain/project-view.ts` — types only, committed by the lead ahead of both lanes.
- `CanvasLibraryRepository`, `CanvasLibrary`, `CanvasWorkspace`, `RecordCommand` — already
  frozen in `src/canvas.ts`.
- The dev-server wire format (`?expectedRevision=N`, `409 {"revision":N}`) — already frozen and
  proven by both sides.

## Lane A — Domain: read model and layout

**Owns:** `src/domain/**` (except `migrate/**`, which is finished).
**Verification loop:** `npx vitest run src/domain` — seconds, no browser, no server.

- A1 Implement `projectView` against the frozen types: join nodes with placements, apply
  collapse and hidden-kind policy, return parent-first ordering.
- A2 `LayoutStrategy` seam: `(graph, target, options) => placements`, pure and deterministic.
  Move the existing dagre hierarchy layout behind it; add `flow`.
- A3 Slice layout: whole-diagram / group / explicit node-set targets, pins honoured, boundary
  groups may resize but nothing outside the target moves.

**Done when:** the same graph and strategy produce byte-identical proposals twice, and a slice
layout leaves every placement outside its target unchanged.

## Lane B — Storage and CLI

**Owns:** `tools/**`.
**Verification loop:** run `./canvas maps`, `read`, `apply`, `snapshot` against the worktree's
migrated records — a real command, not a fixture.

- B1 Bridge hardening: watch `public/data/diagrams/` recursively so external writes still
  trigger the hot reload; keep `/api/preferences` behaviour.
- B2 CLI onto records: one scope block writes one record through the library, as one change set
  with `provenance: { source: 'cli' }`.
- B3 A wire naming a node in another diagram becomes a `CrossDiagramLink` rather than an error,
  so the one real cross-diagram relationship survives a re-apply.

**Done when:** `./canvas apply` round-trips a diagram through records and `./canvas read` prints
it back unchanged.

## Lane C — Web host rendering

**Owns:** `src/presentation/**` (except `work-session-report/**`), `src/App.tsx`, `src/main.tsx`.
**Verification loop:** drive the running app with `~/.claude/browse` — screenshots, not tests.

- C1 Render from `projectView` output; drop `focusArchitecture` / `presentArchitecture` /
  `positionedNodes` from the presentation path.
- C2 Mutations go through `CanvasWorkspace`; autosave through `library.save(diagramId)`, keeping
  the existing stale-revision and save-failed statuses.
- C3 Switching diagrams opens another workspace through the library.

**Done when:** every diagram opens, edits, and saves as a record, demonstrated by screenshots of
each interaction.

## Lane D — Craft (starts after C1 lands)

**Owns:** `src/styles/**`, and inspector components once Lane C has stopped editing them.
Sequenced rather than parallel, because it shares files with C.

## Lane E — Cleanup (last)

**Owns:** deletions across the tree; runs when A, B and C are all green.

Delete `canvas-engine.ts`, `json-repository.ts`, `layouts.ts`, `maps.ts`, and
`ArchitectureDocument` — everything with no remaining caller. `parseArchitectureDocument` and the
v1→v2 step survive: they are the entry to the migration chain.

## Running order

```
freeze contracts (lead)
   ├── Lane A ──┐
   ├── Lane B ──┤ parallel; disjoint files
   └── Lane C ──┘
          ↓
       Lane D
          ↓
       Lane E
```

Each lane reports against its own verification loop. A lane that needs another lane's file stops
and says so rather than editing across the boundary.
